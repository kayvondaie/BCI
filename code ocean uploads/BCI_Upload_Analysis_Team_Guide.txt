================================================================================
BCI DATA UPLOAD + ANALYSIS — TEAM GUIDE
================================================================================

Onboarding instructions for the BCI data workflow: uploading sessions from
your scope rig, monitoring processing, and running analysis on the results.

End-to-end flow:
   ScanImage on rig → staged on VAST → upload script → AIND service →
   S3 → CO pipeline (motion correction + extraction) → processed asset →
   analysis capsule (data_dict + bonsai plots)

Total time per session: ~3 hours (upload ~30 min + pipeline ~2.5 hours).
You only get an email if something fails.

================================================================================
PREREQUISITES
================================================================================

Before you start, make sure you have all of these:

  - Allen network access (VPN or on-site Ethernet)
  - GitHub account (ask Kayvon to add you as a collaborator on:

================================================================================
PART 1 — ONE-TIME SETUP ON YOUR LAPTOP
================================================================================

You only do this once. It installs the upload tool and creates the Python
environment.

Open the Anaconda Prompt (Start menu → "Anaconda Prompt"), then:

  cd C:\github
  git clone https://github.com/kayvondaie/bci-data-uploader.git
  cd bci-data-uploader
  conda env create -f environment.yml

(The env create takes ~5 minutes.)

To activate and use the env each session:

  conda activate bci-uploader
  spyder

A fresh Spyder launches using the bci-uploader env. Verify the env is good
by running this in Spyder's IPython console:

  from aind_data_transfer_service.models.core import UploadJobConfigsV2
  print("env is good")

If "env is good" prints, you're set. If it errors with ModuleNotFoundError,
the env didn't install correctly — re-run "conda env create".

================================================================================
PART 2 — DAILY UPLOAD WORKFLOW
================================================================================

Before uploading, make sure your session is fully staged on VAST:

  \\allen\aind\scratch\BCI\2p-raw\<subject_id>\<mmddyy>\
       behavior\               (Harp + Bonsai outputs)
       behavior_video\         (MainCamera videos)
       pophys\                 (ScanImage TIFFs, CSVs, MAT thresholds)
       session.json            (generated by MetaDataGUI or generate_metadata)
       rig.json                (same)

If session.json and rig.json are missing (e.g., the session was copied
manually rather than staged via the GUI), run generate_metadata first:

  python C:\github\bci-data-uploader\generate_metadata.py //allen/aind/scratch/BCI/2p-raw/<subject_id>/<mmddyy>

Then to upload:

  1. In Spyder, open C:\github\bci-data-uploader\spyder_upload.py

  2. Edit CELL 0 — fill in the same fields you'd type into the GUI:
        SUBJECT_ID         = "843574"          (your subject ID)
        DATE               = "052026"          (mmddyy)
        EXPERIMENTER       = "your.name"
        WAVELENGTH         = 920               (or your wavelength)
        IMAGING_DEPTH      = 122               (or your depth, in micrometers)
        TARGETED_STRUCTURE = "Primary Motor Cortex"
        NOTES              = "anything"
        DRY_RUN            = True              (first time always — preview only)
        TRIGGER_PIPELINE   = True              (auto-runs the CO pipeline)
        FORCE_REUPLOAD     = False             (only set True if re-doing a session)

  3. Run all 3 cells (Ctrl+Enter in each, or F5 to run the whole file).

  4. Read the dry-run output carefully:
        - Subject ID and date correct?
        - Wavelength / depth right for this session?
        - File paths point at the right session folder?
        - "Pipeline: 3b046f6a-1f9d-4cae-a2f1-5a3911bec912" (the kd pipeline)?

  5. If everything looks right:
        - Change DRY_RUN = False in CELL 0
        - Re-run CELL 0, then CELL 1, then CELL 2

  6. CELL 2 should print "Submission accepted" + a JSON response. You're done.

What happens next (no action required from you):
  • ~30 min: data uploads to S3, raw data asset appears in Code Ocean
  • Pipeline auto-triggers against that raw asset
  • ~2-3 hours: pipeline finishes (motion correction + extraction)
  • Processed data asset auto-appears in Code Ocean with name like:
       single-plane-ophys_<subject>_<date>_<time>_processed_<timestamp>

A small file called ".uploaded.json" is written to the session folder so
that if you re-run the script later, it knows the session is already done
and won't double-submit.

PART 3 — CHECKING UPLOAD PROGRESS
================================================================================

You can monitor things in three places.

  (a) Code Ocean Data Assets
      https://codeocean.allenneuraldynamics.org/data-assets
      Search by subject ID + date to find raw and processed assets.
      • Raw asset appears within ~30 min of upload.
      • Processed asset appears after pipeline completes (~3 hours).

  (b) AIND data-transfer-service dashboard
      http://aind-data-transfer-service/
      Lists all upload jobs with their status (queued / running / succeeded /

  (c) The pipeline page in Code Ocean
      https://codeocean.allenneuraldynamics.org/capsule/0242565/
      Timeline panel shows recent runs. Click into a run to see its status
      and per-capsule logs if it failed.

You'll only get an email if processing FAILS. No email = it worked.

================================================================================
PART 4 — RUNNING ANALYSIS IN THE CAPSULE
================================================================================

Once both the raw and processed data assets exist, you can run analysis.

  1. Go to Code Ocean and open the analysis capsule:
        https://codeocean.allenneuraldynamics.org/capsule/<bci-data-dict-capsule-bruker>/
     (find it by name in your Code Ocean capsules list)

  2. Attach both data assets:
        Click "Manage Data" (top right)
        Attach BOTH:
          - raw:       single-plane-ophys_<subject>_<date>_<time>
          - processed: single-plane-ophys_<subject>_<date>_<time>_processed_<timestamp>
        IMPORTANT: Detach any unused data assets first — the capsule has a
        10 GB attached-data limit.

  3. Launch a Cloud Workstation:
        Click "Launch Cloud Workstation" → choose VS Code.
        Wait ~30 seconds for the workstation to start.

  4. In VS Code, open a terminal (Ctrl + backtick) and pull the latest code:
        cd /root/capsule
        git pull origin main

  5. Open code/explore.py.

  6. Edit CELL 2 — the only fields you usually change:
        SUBJECT     = "843574"           (subject ID)
        DATE        = "2026-05-20"       (YYYY-MM-DD format — different from upload!)
        TARGET_STEM = "bci2"             (which epoch to analyze: bci, bci2, spont_pre)

     If your session only has a "bci" epoch (no bci2), use "bci". Look at the
     attached processed asset's motion_correction/epoch_locations.json to see
     what epochs exist for this session.

  7. Run cells in order:
        CELL 1: imports + matplotlib setup
        CELL 2: finds the attached raw+processed assets, builds workspace,
                slices F.npy to the target epoch
        CELL 3: runs ddc.main → produces the `data` dict
        CELL 4: bonsai threshold analysis → produces 2 figures inline

  8. Figures appear in the Interactive Window. To get a Spyder-like separate
     "Plots" panel:
        Hover over a figure → click the expand icon → opens in Plot Viewer
        Drag the Plot Viewer tab to the right edge → splits into its own panel.

If something errors, paste the traceback when reporting to Kayvon.

================================================================================
PART 5 — THINGS TO KNOW / GOTCHAS
================================================================================

  • Auto-capture only fires when you upload through spyder_upload.py.
    If you manually click "Run with parameters" in Code Ocean, no processed
    asset is auto-created — you'd have to capture it yourself, and that
    risks mislabeling. Always upload through the script.

  • Don't interrupt git operations in the capsule terminal. Interrupted
    fetches/pushes leave large temp pack files in .git that count against
    the 10 GB capsule limit. If you suspect this happened:
        du -sh /root/capsule/.git
    If it's huge, clean up:
        git -C /root/capsule gc --prune=now

  • Pipeline takes ~3 hours per session. Not real-time.

  • BCI vs BCI2: if your session has multiple BCI variants (different
    epochs with stems like "bci_" vs "bci2_"), the analysis capsule's
    CELL 2 lets you pick which to analyze via TARGET_STEM. The pipeline
    extracts both correctly as separate epochs.

  • Use the EXACT same DATE format the upload service used. The asset is
    named with YYYY-MM-DD (e.g., "2026-05-20"), even though you typed
    mmddyy ("052026") in the upload script. CELL 2 in the analysis capsule
    expects YYYY-MM-DD.

  • The capsule's git is on GitHub. To get the latest analysis improvements:
        cd /root/capsule && git pull origin main

  • To save figures to disk for export:
        for i, f in enumerate(figs):
            f.savefig(f"/results/figure_{i}.png", dpi=150, bbox_inches="tight")

================================================================================
PART 6 — TROUBLESHOOTING
================================================================================

"No raw/processed asset attached" in CELL 2
   → Verify both assets are attached in the capsule's Data panel.
     Detach any duplicates or stale versions of the same session.

Pipeline failed at motion correction
   → Common cause: ROI rejection by suite2p classifier for the conditioned
     neuron, or bad metadata in session.json. Check the run page in CO for
     the specific error and report to Kayvon.

ModuleNotFoundError in Spyder
   → Wrong conda env active. In Anaconda Prompt:
        conda activate bci-uploader
        spyder
     (NOT just clicking the Spyder icon from Start menu — that uses the
     base env, which doesn't have these packages.)

"Capsule Limit" full warning in CO
   → Probably the .git directory has stale pack files. In the workstation:
        cd /root/capsule
        du -sh .git
     If huge (>1 GB), run: git gc --prune=now

"Already uploaded — skipping submission"
   → A previous upload of this session succeeded. The .uploaded.json
     marker is in the session folder. To re-upload anyway, set
     FORCE_REUPLOAD = True in CELL 0, or delete the .uploaded.json file.

Spyder can't find spyder_upload.py
   → Make sure you cloned the repo to C:\github\bci-data-uploader, OR
     update the path in your Spyder open-file dialog.

APPENDIX — WHAT THE PIPELINE PRODUCES
================================================================================

A successful end-to-end run gives you, in the processed data asset:

  motion_correction/
      <session>_registered.h5         Motion-corrected movie (single H5)
      epoch_locations.json            Frame ranges per epoch (e.g., spont_pre,
                                      bci, bci2)
      trial_locations.json            Frame ranges per TIFF file
      <various PNG QC plots>

  extraction/
      F.npy, Fneu.npy, spks.npy       Combined traces across all non-photostim
                                      epochs
      stat.npy, iscell.npy, ops.npy   Per-ROI suite2p outputs
      <session>_extraction.h5         AIND-standard combined output (h5)
      suite2p_bci/plane0/             Per-epoch sliced traces (BCI)
      suite2p_bci2/plane0/            Per-epoch (if you have a bci2 epoch)
      suite2p_spont_pre/plane0/       Per-epoch (spontaneous activity)

The analysis capsule's CELL 2 picks the per-epoch you want via TARGET_STEM
and uses the COMBINED F.npy (re-sliced) for the cleanest data, since the
per-epoch folders sometimes have edge cases.
